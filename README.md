# Live Global Slavery & Child Labour Map

A self-contained map of forced labour, bonded labour, trafficking and child
labour worldwide: where it is documented, who profits, and — first — where a
person in it gets help, where a third party reports someone, who takes the
legal case, and where money goes.

---

## Repo layout

```
.
├── index.html            the map (2.3 MB, self-contained)
├── trackerdata.json      country + region directory   → must be deployed
├── wire.json             generated by harvest_wire.py → optional, see below
├── projects.json         determinations layer         → not built yet
├── harvest_wire.py       builds wire.json from the feed list in index.html
├── harvest_determinations.py  builds projects.json from published customs orders
├── harvest_cases.py      builds cases.json from CTDC identified-case records
├── harvest_scale.py      builds prevalence.json (Walk Free) and directory.json (GMSD)
├── harvest_points.py     builds points.json (IPIS mines, brick kilns, OSH) + hotlines.json
├── harvest_bulk.py       builds bulk.json (Brazil municipalities, UNODC, IUU, GFW)
├── bundle.py             folds every layer into one self-contained index.bundle.html
├── verify_links.py       link checker for every URL that ships
├── smoke_test.js         runs the page and fails on any uncaught error
├── package.json          jsdom, for smoke_test.js only
├── .nojekyll             empty file; stops Pages eating _-prefixed paths
├── BUILD-NOTES.md
└── .github/workflows/
    ├── wire.yml          harvest every 6h, commit wire.json
    └── check.yml         smoke test + link check on push
```

## One file, if you want one

`python3 bundle.py` writes **index.bundle.html** with the data layers embedded
— a single self-contained file you can upload, email or drop into any host with
nothing beside it. The workflow rebuilds it after every harvest, so there is
always a current one in the repo.

**One layer is deliberately left out: `infra.json`** — 3,630 ports, which
embedded to 2.1 MB, a quarter of the file, for the layer least likely to be why
anyone opened the map. Deploy it next to the bundle and the ports appear;
`bundle.py --embed infra.json` folds it back in.

The runtime is unchanged: the map still prefers a real JSON file on disk and
only falls back to the embedded copy. So the bundle works alone *and* picks up
fresh harvest output when deployed next to it. Bundling adds a floor; it does
not freeze anything.

## Everything runs on GitHub. Nothing runs on your computer.

All harvesters execute in GitHub Actions, write their output into the repo, and
commit it. You never run Python locally. The only manual step is for the four
sources whose publisher has no stable file URL — for those, download the export
once in a browser and **commit it to `data/`**; the harvesters find it there
automatically by filename and use it on every scheduled run.

```
data/
├── resgates_brazil.csv     Observatório export (municipality rescues)
├── glotip_unodc.csv        dataunodc.un.org country table
├── ctdc_synthetic.csv      CTDC Global Synthetic Dataset
├── gsi_prevalence.xlsx     Walk Free country data
└── kilns.csv               SentinelKilnDB coordinates (optional)
```

Name them with any filename containing the keyword above — `resgat`, `glotip`,
`ctdc`, `gsi`, `kiln` — and they are picked up without editing anything.

One caveat worth knowing: GitHub's runners come from cloud IP ranges, and a few
publishers block those. If a source works in your browser but 403s in Actions,
that is why, and the export-to-`data/` route is the fix for it too.

## Setup

```bash
git init && git add . && git commit -m "initial"
git remote add origin git@github.com:WelcomeToYourGalaxy/<repo>.git
git push -u origin main
```

Then **Settings → Pages → Source: `main` / root**. It serves at
`https://welcometoyourgalaxy.github.io/<repo>/`.

To embed in Weebly, use an Embed Code element pointing at that URL:

```html
<iframe src="https://welcometoyourgalaxy.github.io/<repo>/"
        style="width:100%;height:90vh;border:0"
        title="Live Global Slavery & Child Labour Map"></iframe>
```

Do not paste `index.html` into Weebly directly — it is 2.3 MB and Weebly's
editor will mangle the inline scripts.

## Tests

```bash
npm install                     # jsdom
node smoke_test.js              # executes the page, exit 1 on any error
python3 verify_links.py --csv report.csv
```

`smoke_test.js` exists because a data-level validator cannot catch a code-level
break. An edit once silently deleted `var facActive={...}` from the end of a
line; every data check passed and a fatal `ReferenceError` shipped. This
executes the page and would have failed.

Read the link report by status: `DEAD` needs fixing, `BLOCKED` (401/403/429) is
a live site refusing a script — open it by hand before touching the entry.

## Harvesters

Both exit non-zero and write nothing if every source failed, rather than
overwriting good data with an empty file — a scheduled run during an outage
would otherwise blank the live layer silently. `--force` overrides.

```bash
python3 harvest_determinations.py      # writes projects.json
python3 harvest_cases.py               # writes cases.json
python3 harvest_scale.py --all         # writes prevalence.json, directory.json
python3 harvest_points.py --all        # writes points.json, hotlines.json
python3 harvest_bulk.py --all          # writes bulk.json
python3 harvest_wire.py --days 30      # writes wire.json
python3 harvest_wire.py --dry-run -v   # show what would ship
```

Reads the feed list out of `index.html`, so there is one canonical list. Tags
country and region at harvest time against the full country list — not in the
browser, which is where the sibling map's empty subregion filter came from.

### .github/workflows/wire.yml

```yaml
name: harvest wire
on:
  schedule: [{cron: "0 */6 * * *"}]
  workflow_dispatch:
permissions: {contents: write}
jobs:
  harvest:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with: {python-version: "3.12"}
      - run: python3 harvest_wire.py --days 30
      - run: python3 harvest_determinations.py
      - run: python3 harvest_cases.py || true
      - run: python3 harvest_scale.py --all || true
      - run: python3 harvest_points.py --ipis --hotlines || true
      - run: python3 harvest_bulk.py --glotip --iuu || true
      - run: |
          git config user.name  "wire-bot"
          git config user.email "wire-bot@users.noreply.github.com"
          git add wire.json projects.json cases.json prevalence.json directory.json points.json hotlines.json bulk.json
          git diff --staged --quiet || git commit -m "wire: $(date -u +%F\ %H:%M)"
          git push
```

### .github/workflows/check.yml

```yaml
name: checks
on: [push, workflow_dispatch]
jobs:
  smoke:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: {node-version: "20"}
      - run: npm install --no-audit --no-fund
      - run: node smoke_test.js
  links:
    runs-on: ubuntu-latest
    continue-on-error: true          # third-party outages are not our failures
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with: {python-version: "3.12"}
      - run: python3 verify_links.py --csv report.csv
      - uses: actions/upload-artifact@v4
        if: always()
        with: {name: link-report, path: report.csv}
```

## If the map looks blank

Open the console and run `mapDiag()`. It prints zoom, whether the painted plate
is attached and held, satellite and boundary tile status, tiles loaded, tile
errors, directory size and live incident count. The plate now stays up if Esri
imagery fails, and the map key says so.

## Standing rules

- **No fabrication.** An entry ships only if the organisation and URL are known
  to exist. A slot with no confident entry stays empty rather than plausible.
- **Run `verify_links.py` before every deploy.** A dead link is a defect.
- **Re-run `smoke_test.js` after any edit to `index.html`,** and the taxonomy
  cross-check after any edit to `trackerdata.json` — mistyped tags fail silently
  at runtime.
- **Nothing is geocoded to a site.** Country and region centroids only. A
  precise dot on a live case exposes the people still in it.
